## Статус тестового прогона

**Полный прогон через живой Hermes Agent пока не выполнен.** В предоставленных материалах есть `questions.txt`, но нет самих CSV-файлов датасета, а в этой среде нет подключения к пользовательскому Hermes API Server. Поэтому в таблице ниже нет выдуманных ответов, чисел или длительности. Автотесты приложения — это отдельная проверка и не доказывают правильность бизнес-аналитики.

## Общая процедура запуска

1. Поднять приложение по инструкции из [README.md](README.md) и запустить `hermes gateway`.
2. Проверить доступность Gateway: `GET http://127.0.0.1:8642/v1/health`.
3. Проверить набор инструментов: `GET http://127.0.0.1:8642/v1/toolsets`. Для аналитических задач нужны как минимум `execute_code` и `terminal`; файловые tools нужны для работы с файлами и артефактами.
4. Скачать CSV-файлы из HK_Datasets. При размере входного файла больше 20 МБ увеличить `MAX_UPLOAD_MB` в `.env`. Текущий CSV-профайлер читает файл целиком в память, поэтому учитывать доступную RAM.
5. Запустить каждый вопрос в отдельной новой сессии Hermes Chat и прикрепить указанный датасет. Не отправлять агенту несколько вопросов подряд в одной сессии, чтобы результаты не смешивались.
6. Сохранить точный ответ, все приложенные артефакты и время выполнения. Проверить расчёт отдельно независимым скриптом или SQL.
7. Заполнить протокол каждого кейса ниже: фактический ответ, сверка, PASS/FAIL и замечания.

## Как закрыть BLOCKED

Когда появятся CSV-файлы и будет доступен Hermes Gateway, выполните шесть вопросов по инструкции выше. Для каждого теста замените статус на `PASS` или `FAIL`, вставьте дословный ответ агента, приложите артефакт и запишите результат независимой сверки. Не ставьте `PASS` только потому, что модель выдала уверенный ответ: числовые агрегаты должны быть перепроверены.
